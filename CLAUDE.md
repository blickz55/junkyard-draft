# Junkyard Draft — project instructions

Two linked deliverables live in this repo:
1. **Junkyard Draft** — 2D factory score-attack game (TypeScript + Phaser 3.90 + esbuild). `game/`
2. **Workshop Control Room** — read-only live development dashboard fed by Claude Code hooks. `control-room/`, `.claude/hooks/`

Read `docs/STATUS.md` (what works, next task) and `docs/ROADMAP.md` (acceptance criteria) before changing anything. `docs/PRODUCTION-ROADMAP.md` is the plan of record from 0.7.0 to 1.0 (milestones, policies, the owner's decisions); `docs/DESIGN.md` holds the rules; `docs/CONTINUE.md` is the resume recipe.

## Commands (verified)
- `npm run dev:all` — game dev server (http://127.0.0.1:5173) + Control Room (http://127.0.0.1:4310)
- `npm run dev` / `npm run control-room` — each alone
- `npm run typecheck` · `npm test` = `npm run test:unit` (every `tests/*.test.ts` with coverage over `game/src/sim` and `server`, floors lines 95 / branches 85 / functions 88) then `npm run test:e2e` (the browser files on free ports through `tests/e2e/fixture.mjs`; needs `PLAYWRIGHT_BROWSERS_PATH` if browsers are not in the default cache); `npm run test:timing` runs the two timing-sensitive tests (bot par, storage measurement) uninstrumented at the end of `test:unit`; `npm run test:quick` is the unit glob without coverage · `npm run lint` (ESLint flat config) · `npm run format` / `format:check` (Prettier, 160 columns). Browser tests never sleep: wait for a condition through the fixture's helpers; a deliberate pause is `settle(ms, why)`
- `npm run verifier` (dev, tsx) · `npm run verifier:build` → `server/dist/verify.mjs` · `node server/dist/verify.mjs --host 0.0.0.0 --data-dir /data` (prod; see `server/README.md`, `Dockerfile`) · `VERIFIER_URL=https://… npm run build` bakes the default verifier into `dist/`
- `npm run build` — reproducible production bundle in `dist/` (served by the Control Room at `/verified/`); Phaser comes from `game/phaser-entry.cjs` (0.10.2: only the modules the game uses, built from `phaser/src`; `scripts/esbuild-config.mjs` aliases `phaser` to it) · `node --import tsx tools/bundle-size.ts [--max 300]` — the bundle's gzip weight against the budget · `node --import tsx tools/first-interactive.ts [--budget 4000] [--runs 3]` — time to a tappable title on slow 4G from a static server over `dist/` · `node --import tsx tools/perf.ts --device D --speed 1 --renderer canvas` then `tools/perf-gate.ts … --p95 33` — the preset D budget (`perf.yml` runs all three)
- `npm run desktop` — Electron window over `dist/`; `npm run desktop:pack` — build + unpacked desktop app in `release/win-unpacked/` (electron-builder, config under package.json `build`); `npm run desktop:icon` — re-render the icon PNG from `desktop/build/icon.svg`; `npm run desktop:dist` — unpacked app + NSIS installer in `release/`; `npm run test:desktop` — packaged-app smoke test (also part of `npm test`, skipped when no build exists)
- `node tools/playwright-shots.mjs <url> <name> --task <id> --note "..."` — screenshot + register in the Control Room
- `node --import tsx tools/make-sfx.ts` — re-render the two impact samples (`game/public/sfx/*.wav`, deterministic)
- `node --import tsx tools/make-golden.ts` — regenerate the golden replay corpus under `tests/golden/` (only after a deliberate `RULES_VERSION` bump; `tests/golden.test.ts` re-simulates every file and checks its final-state and per-round event hashes); `--digests` rewrites only those hashes in `INDEX.json` from the files on disk (0.8.11) · `tests/engines-e2e.test.mjs` re-simulates the corpus in Chromium, Firefox and WebKit against those hashes (`npx playwright install firefox webkit` locally; engines missing here are skipped, CI's `engines` job requires all three) · `node --import tsx tools/determinism-lint.ts` — no clock, locale, transcendental Math or bare `sort()` under `game/src/sim/` (`tests/determinism-lint.test.ts`) · `node --import tsx tools/image-smoke.ts <verifier-url> [--expect-entries N]` — health + legal submission + board check against a running verifier (CI runs it against the Docker image) · `node --import tsx tools/mint-check.ts <verifier-url> [--date D] [--secret S]` — today's minted daily seed verified against yesterday's published commitment, and this week's weekly against the previous week's (PLAN-v3 0.6.1, PLAN-v4 0.7.5; CI runs it too)
- `node --import tsx tools/storage-measure.ts [--players 100,1000,10000] [--days 30] [--out …]` — board.json size and commit latency for synthetic boards at the retention caps, against the SQLite trigger (5 MB / 50 ms); baselines in `docs/baselines/0.6/storage*.json` (PLAN-v3 0.6.7); `--split` also moves closed days older than 30 to cold storage and reports the hot file (PLAN-v4 0.7.0, `docs/baselines/0.7/`)
- `node --import tsx tools/load.ts <verifier-url> [--rate 60] [--ips 3] [--minutes 2] [--budget 100] [--json out]` — flood a verifier (started with `TRUST_PROXY=1`) with distinct legal replays from simulated addresses while sampling `/health`; exit 1 over the latency budget (production roadmap 0.8.2; baseline `docs/baselines/0.8/load-0.8.2.json`) · `docker logs verifier 2>&1 | node --import tsx tools/log-check.ts` — fails when a request log line carries an address or a group code (0.8.1; CI runs it)
- `node --import tsx tools/backup.ts <data-dir> --out <dir | remote:path> [--keep 14]` — archive a verifier data directory with a hash manifest (never the secret) to a local directory or an rclone remote · `node --import tsx tools/restore-drill.ts <archive> [--live <url>] [--sample 5]` — unpack, verify hashes, start a verifier on the copy, compare counts and sampled scores (production roadmap 0.8.3; VPS schedule in `deploy/backup.cron`)
- `node --import tsx tools/moderate.ts <verifier-url> list|clear <playerId>|confirm <playerId>|rename <playerId> <name>|rename-group <code> <name> [--token T]` — name moderation against a running verifier started with `MODERATION_TOKEN` (PLAN-v4 0.7.7; the audit log is `moderation.jsonl` next to the board)
- `node --import tsx tools/hosted-check.ts <site-url> [--submit-daily] [--name N] [--no-headers] [--json out]` — the hosted acceptance (headers incl. the CSP header, build.json, the baked verifier's health and CORS, the page in Chromium with the daily board filled, optionally one real daily submission); `deploy/` holds compose, Caddyfile, the `_headers` template the build renders into `dist/_headers`, env templates and the runbook `deploy/README.md` (0.8.5); `.github/workflows/deploy.yml` deploys after a green `ci` run once the repository variables exist. Note: the production bundle is `dist/main-<hash>.js` (`build.json` names it); the dev server still serves `/main.js`
- `node --import tsx tools/make-foreman-snapshot.ts` — regenerate `tests/fixtures/foreman-snapshot.json` (the foreman's chosen line per situation and UTC day; `tests/foreman.test.ts` holds the code to it) after changing `game/src/content/foreman.ts` or a `foreman.*` line; `docs/FOREMAN.md` is the character sheet (0.9.1)

- `node --import tsx tools/strings-lint.ts` — no prose literal outside the string table in `game/src/ui` and `game/src/content` (0.9.0; `tests/strings.test.ts` also holds the table to the banned-word glossary in `game/src/content/glossary.ts`). ## Environment notes
- **Primary home (since 2026-10-25): the user's Windows 11 PC, `C:devjunkyard draft`** (Node 24, npm 11, git with autocrlf; `.gitattributes` forces LF). `npm install` works; Playwright's Chromium comes from `npx playwright install chromium` (default cache, no env var needed); Electron 45 is a devDependency and `npm run desktop` opens the built `dist/` (run `npm run build` first). `.claude/launch.json` has a `game` config (`npm run dev:all`, port 5173) and a `control-room` attach config (4310) for the desktop app's browser pane.
- Cloud sandbox (where the first session ran): the npm registry is unreachable, `node_modules/` is symlinked to preinstalled tools (esbuild 0.28, tsc 6.0, tsx, playwright 1.63 with Chromium at `/opt/pw-browsers`) and `vendor/phaser/` carried Phaser 3.90.0 with a default-export shim; since production roadmap 0.9.5 that folder is not in Git (`.gitignore`), so a sandbox restores it first: `mkdir -p vendor/phaser`, copy the preinstalled package's `dist/phaser.esm.js` and `types/` there, write `index.js` (`import * as Phaser from './phaser.esm.js'; export default Phaser; export * from './phaser.esm.js';`) and a `package.json` (`main`/`module` `index.js`, `types` `types/phaser.d.ts`), then symlink `node_modules/phaser` to it (tsconfig `paths` keeps the vendor fallback). On a normal machine the vendor copy is unused (tsconfig `paths` and node resolution prefer `node_modules/phaser`). The browser tests only set `PLAYWRIGHT_BROWSERS_PATH` when `/opt/pw-browsers` exists.
- `scripts/dev.mjs` and `scripts/build.mjs` use esbuild directly (Vite was not installable in the sandbox). Keep both scripts working; do not add a second build path. `.dev-build/` and `dist/` are build output and stay out of Git. After editing `scripts/esbuild-config.mjs` (defines such as `import.meta.env.VERIFIER_URL`) restart the dev server: a running watcher keeps the define map it started with.

## Rules of the road
- Player-facing words come from the string table and follow the glossary (0.9.0): yard, second, shift, checked, recording, the shelf, crews, "beat this", a try, your key; never seed, tick, verifier, replay, hash, histogram, percentile, reroll, bin, token (the policy page excepted). The lint fails the suite otherwise.
- `game/src/render/scenes/GameScene.ts` keeps only its 0.9.4 responsibilities (349 lines before the 0.9.5 Prettier pass, about 680 after it; do not grow it with new concerns): input belongs in `render/InputController.ts`, hints in `render/guide.ts`, sprites and per-tick effects in `render/SimView.ts` (+ the pure `render/simframes.ts`), the stall indicator in `render/StallMonitor.ts`, pops in `render/PopPool.ts`, the funnel in `render/GameTelemetry.ts`, the build overlay in `render/FlowOverlay.ts`; each has a unit test under `tests/`.
- Simulation (`game/src/sim/`) is pure, deterministic and browser-free. Rendering never influences outcomes. Bump `RULES_VERSION` when any rule or tuning value changes and keep replay verification tests green. Scenario namespaces (`tutorial-*`) are part of the rules: a change to what a reserved seed does is a rules change too (review F13). The golden corpus in `tests/golden/` pins existing replays; it is regenerated only together with a version bump.
- Layout (0.10.0): there is no fixed canvas size. The canvas fills `#game` (`render/viewport.ts`); the yard is drawn in board-logical px (`render/layout.ts`: `GRID_X/Y`, `CELL`, the shelf) and `GameScene.layoutBoard` fits the camera to the `.jd-board` slot the CSS-grid shell in `ui/GamePanel.ts` lays out by media query (`COMPACT_MQ`, `LANDSCAPE_MQ`, `TABLET_MQ`). DOM elements anchored to cells use `em(px)` with `--px` from the slot; chrome uses plain em. Tests never hard-code board coordinates: they use `page.jd.at()` / `drag()` with `cellCenter`, `binSlotCenter`, `shelfPoint` markers resolved from `window.__jd.geometry()`. Any layout change runs `tests/layout-e2e.test.mjs` (six viewports at 130 %) and keeps 46–50 px cells on a 390–430 phone; `MAX_BOARD_SCALE` stays 1 (a scaled sprite is a slower blit on the Canvas renderer; the perf gate on preset B measures it).
- Push (0.10.4): `server/push.ts` sends one message a day, "The yard is open", and nothing else until 0.11.7; `web-push` is the only runtime dependency (the production roadmap's rule 6: one at a time, by decision, recorded in `server/README.md`); the verifier needs `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` (⚑ the owner's) or the push routes answer 503. `tests/push.test.ts` holds the request format against a mock endpoint; never test against a real push service.
- The web app (0.10.3): `game/sw.js` is a template the build fills (`scripts/build-lib.mjs`); a new static file under `game/public/` joins the shell cache by itself, a new route or origin does not (other origins are never cached). The dev server serves no worker (`?sw=1` registers one in dev). `node tools/make-icons.mjs` re-renders `game/public/icons/` from `desktop/build/icon.svg`. The title is the only screen that announces a waiting update or offers the install (`render/pwa.ts`); `tests/pwa-e2e.test.mjs` must keep playing offline from the cache and rolling an update over between runs.
- Phaser (0.10.2): a new Phaser feature (a game object, a loader type, a scene plugin, a namespace) is a `require` in `game/phaser-entry.cjs` or it does not exist at runtime, whatever TypeScript says; the bundle must stay under 300 KiB gzip (`tools/bundle-size.ts`, gated in `perf.yml`). The entry needs the npm package's `src/` (the sandbox's `vendor/phaser` has only `dist/`).
- Input (0.10.1): `game/src/content/controls.ts` is the one action table. A new shortcut or gesture is a row there (its keys bind from the table in `render/InputController.ts`; the Tips panel and the build panel's keyboard line read the same rows); mouse, touch and keys all end in the same rule-checked actions. `tests/touch-e2e.test.mjs` must still play six rounds with touch events only.
- The record page (`ui/RecordPanel.ts`, 0.9.7) reads local storage only; the standings, medals and kinds it shows are written where the game learns them (`recordStanding`, `recordMedal`, `recordKinds` in `render/storage.ts`), never fetched.
- Scores are local and unverified until a server re-simulates replays. Never label local bests as verified; never invent competitors.
- Dev-only hooks (`window.__jd`) exist for automated play. They apply rule-checked actions and carry no scoring authority.
- Every meaningful increment: implement → `npm test`/typecheck → launch and exercise in Chromium → look at the screenshot → commit → `emit.mjs checkpoint` → update `docs/STATUS.md`.
- Keep Control Room instrumentation alive: emit `objective` when the goal changes, `task` on stage changes, `check` only from actual results, `screenshot` for captures, `checkpoint` on commits. Raw telemetry (`.control-room/events.jsonl`, screenshots, reports) stays out of Git.
- Never fabricate test results or screenshot observations. If a check cannot run, say so in STATUS.
- Commit messages end with the Co-Authored-By / Claude-Session trailer used in the existing history.
