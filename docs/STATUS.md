## Session 2026-10-30 (48) — production roadmap 0.8.2 re-simulation in a worker, single pass (main, no rules change, protocol 2)
- `server/verify.ts`: a submission is now three steps. `prepare()` (synchronous, no simulation): decode, rules version, duplicate (an identical resubmission — same hash, same claimed score — is refused before any simulation; the same actions with a different claim still go through the run and fail as a mismatch, as before), issued seed. `resimulate()` (pure, exported): ONE run of the replay gives score, last-round machine count and per-round earnings (`verifyReplay`, `finalMachinesOf` and `roundsOf` each ran it before: three runs per submission); `finalMachinesOf`/`roundsOf` stay as thin wrappers over one `simulateOnce()`, and `deriveTieBreaks` runs each legacy entry once. `record()` (synchronous): judges the re-simulation, applies the window, keep-best and retention, commits. `submit()` = the three inline (tests and tools unchanged). Every refusal carries a reason `code` beside `error` (`RefusalCode`: bad-replay, rules-version, duplicate, unissued-seed, illegal-action, unfinished, did-not-reproduce, resim-timeout, busy, rate-limited, too-large, bad-request, storage); successes carry none.
- `VerifyService`: one re-simulation at a time in a persistent worker thread (this module loaded with `workerData.resimWorker`, spawned on first use, `unref`, replaced after a timeout or a crash), a bounded FIFO (`RESIM_QUEUE` 32 waiting behind the running one; an idle service always takes a job), a wall-clock cap per job (`RESIM_CAP_MS` 10 s); `verify()` rejects with `QueueFullError` at once or `ResimTimeoutError` at the cap; `compute` injectable for tests; `close()` on shutdown (`installShutdown` gained `after`). The HTTP path: `prepare` → 422 with a code, else `verify.verify()` in the worker → `record` on the loop; 503 `busy` with Retry-After 5 when the queue is full, 422 `resim-timeout` at the cap, nothing recorded in either case; `RESIM_INLINE=1` keeps the old inline path for debugging; servers created without a service (tests, tools) run the single pass inline. `/health` adds `resim { jobs, timeouts, queued, busy, capMs, maxQueue }`.
- Per-seed index: the board is behind a private accessor that drops a lazily built `Map<seed, sorted entries>` on every change; `rank()` reads a seed's slice from it (labels still resolve at read time), and the retention pass sorts only the submitted seed, taking every other seed's order from the index (it re-sorted every seed on every write before).
- `tools/load.ts <url> [--rate 60] [--ips 3] [--minutes 2] [--budget 100] [--json out]`: distinct legal replays per simulated address (X-Forwarded-For; target started with `TRUST_PROXY=1`) while `/health` is sampled every 250 ms; exit 1 over the budget.
