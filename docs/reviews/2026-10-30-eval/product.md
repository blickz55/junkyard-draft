## 1. Feature inventory as built

**Core loop.** 6 rounds × (draft 1 of 3 → arrange on 8×6 → 80 ticks → result). 7 draftable kinds (hopper, conveyor, splitter, crusher, furnace, press, tuner from round 3; Sieve exists in the sim with weight 0), 5 materials ($1/$3/$8/$12/$1 slag), starter line of 5 machines, sell-from-bin $10, one paid reroll per round ($40, own RNG stream), tie-break by fewer round-6 machines. Pure deterministic sim with a replay format, `RULES_VERSION` 3, an 11-file golden corpus, action budget 4000. Instant retry / random seed / custom seed / import replay. Save and continue of an unfinished run.

**Onboarding.** `tutorial-1` seed: three scripted rounds (crusher, furnace, splitter + side-load merge, 3 spare conveyors) with a live hint strip that checks the real layout (fed-ness via `placementWarning`, flow via a 40-tick real simulation), then rounds 4–6 as a normal draft; `setOnboarded()` after round 3. Tips panel: 7 tips, 6 with live mini-sims drawn from the real textures, each asserted by `tests/tips.test.ts`; the tip for a newly drafted machine is suggested with a ● badge on the Tips button. Placement refusals explained (`explainRunError`), legal-but-useless placements warned ("Heads up: Furnace takes items from behind only…"). Undo/redo within a build phase. "New here?" hint on the first draft. Rotating hint strip with 7 one-liners.

**Feedback / juice.** The event → sound → visual table in DESIGN is implemented: 8-frame belts, crusher jaw frames, press ram frames, furnace tint, transform rings, pooled `+$` pops, dock lid lift, HUD pulse, jam red wash, stall marker + HUD line after 8 silent ticks, round-end stagger settle. Synth audio on three buses (ui / factory / music), ship chord by value, transform tiers, throttled jam noise, fanfare good/bad with ducking, a throughput hum drone that tracks items in flight and detunes on jams, two authored impact samples. Reduced-audio mode. No music track (the "music" bus carries only fanfares, settle and hum).

**Accessibility.** Keyboard-only placement (arrows, Enter, Tab, R, Delete, Esc), reduced motion following the OS preference, text size 100/115/130 % through one helper with e2e geometry checks, WCAG AA on every pair and CVD-distinct materials plus distinct silhouettes (audited by `npm test`), ARIA roles on dialogs/tabs, focus trapping. Not yet: screen-reader mirror of the grid, key remapping, gamepad, touch, single-step while paused, localisation (all PLAN-v5 0.8.x).

**Daily / weekly / archive / streak / medals.** Server-minted daily `daily-YYYY-MM-DD-xxxxxxxx` with a published commitment to tomorrow, 48 h window from 00:00 UTC, freeze, late runs verified but unranked, archive of closed days playable as practice, weekly from Friday 18:00 UTC for seven days (no modifier), medals at nearest-rank 50/80/95 only once ≥ 5 runs, days played + streak with yesterday's open daily as grace and no loss copy. Offline: practice seed `daily-YYYY-MM-DD`, honestly labelled "practice (unranked)".

**Identity.** Device key → `player_id = SHA-256(key)`, `Name#TAG`, recovery code (base32), one best entry per (player, seed), rename every 24 h, `DELETE /me`, name filter with a 9-word blocklist and look-alike folding. No accounts, no passwords, no e-mail.

**Verified boards / histogram / par.** Board per seed (top 5 on results, top 100 for rank), histogram with "better than N % of n", around-me list, bot par per seed computed in a verifier worker (the shipped greedy autoplayer's median), reveal gate for other players' replays on an open daily. The results screen is histogram-first by design; local scores are consistently labelled unverified.

**Replays / watch.** Every verified entry stores actions (top 100 per seed, top 10 in cold storage); the client re-verifies before playback; REPLAY banner, original earnings per round beside the live total, 1/2/4×, Skip, Stop. Import replay JSON from the title.

**Social.** Challenge link (per-round earnings overlay, outcome line; no layout leaks), groups by 8-char code scoping board/histogram/daily/archive (5 per player, 50 members, no chat), fork from round N into practice (labelled, never submittable, separate fork bests), spoiler-free glyph-grid share text + detailed variant + optional permalink, 1200×630 share card PNG rendered locally, WebM loop clip and GIF of the best round, Discord webhook (seed open / new #1 / freeze) on the verifier side.

**Moderation.** Report a name from a replay (five reasons, no free text), hidden as "player" until a moderator clears/renames, two-clears rule, audit log `moderation.jsonl`, `tools/moderate.ts`. `APPEAL_CONTACT` is a placeholder.

**Desktop.** Electron 45 shell over `dist/`, electron-builder unpacked app + NSIS installer (unsigned), packaged smoke test, clip/card saving through a preload bridge, Linux target declared but never built, no macOS, no auto-update, no code signing.

**Dev-only / unhosted.** `window.__jd` (dev builds or `?dev=1`), the Control Room dashboard, autoplay/balance/perf/a11y tools, telemetry collector (opt-in, 25-event vocabulary). **Nothing is hosted**: no verifier URL is baked into a public build, so every verified/social/daily feature above is true only against `npm run verifier` on localhost. That single ⚑ (0.6.8 = 0.7.8) has been the gate since M4 and is still open. There has been **no recorded human playtest** (M1 ⚑ open since 0.2; `docs/PLAYTEST.md`, referenced by ROADMAP 0.5.7, does not exist in `docs/`). The game has been exercised only by its author's sessions, e2e tests and bots.

## 2. Depth and variety

**Nominal decision space.** Offers: rounds 1–2 draw from 7 kinds (round 1 always includes a crusher → 15 possible triples), rounds 3–6 from 8 (56 triples). Picks: 3 per round, 6 per round with the reroll, so ≤ 6^6 = 46,656 pick paths per seed before money gating. Layout: at most 11 machines (5 starter + 6 picks) on 48 cells with 4 facings — astronomically many placements, but the sim's constraints collapse them: processors and splitters only accept from behind, a hopper gives 40 items per round, a crusher clears 40, an untuned furnace 26, a tuned one 40. In practice a run is one of a handful of topologies:

1. the straight line hopper → crusher → furnace → dock (reached by almost every player by round 2);
2. (1) + a tuner on the furnace (the Tuner study: picked 59 % of the time it is offered, +$187 mean, 0 seeds worse — it is simply correct);
3. a splitter feeding two furnaces, or two hoppers feeding two crushers;
4. a press branch when furnaces are scarce or the dock belt is the bottleneck (press pick rate 34 %, +$44 when taken).

**How quickly a player sees everything.** My own run is the evidence: with the obvious line and a tuner the per-round earnings plateaued at $444–446 from round 3, and rounds 4–6 added nothing that the hopper's 40-items-per-round cap did not already decide (two drafted hoppers had nowhere to feed because the single crusher was the next bottleneck and no second crusher came until round 6). Three of six rounds were dead. The autoplay baseline confirms this is systemic: `flatRoundsTotal` 29 over 20 seeds × 6 rounds (24 % of all rounds change nothing for the greedy bot), one "mostly flat" seed, one seed that never reaches an ingot. The greedy bot's spread is **min $1138 · p25 $1594 · median $1748 · p75 $2058 · max $2470**, i.e. the seed (which offers appear) moves the ceiling by ±40 %, while the starter line alone is $228 and the derived sanity bound is $20,220 (meaning the theoretical envelope is far above anything reachable — the cap is the offer stream, not skill). The reroll study closes some of that gap (+$246 mean, +14 %, losses bounded at the $40 price) but it is a bet on the RNG, not a skill expression. A player who understands "crusher → furnace → tuner, second line when hopper+crusher come together, sell everything else" has the full strategy inside ~10 runs (≈ 1–1.5 hours). After that a daily's result is mostly "did the seed give me the second line in time", which is exactly what a daily must *not* be.

**Dominant strategy and draft tension.** Crusher + furnace + tuner is dominant and unconditional; hopper is the correct pick in 27 of 120 bot picks and conveyor/splitter/dock are mostly sell-fodder (splitter 4 picks, dock 9, conveyor 7). The press is designed to be "clearly below the furnace per shard" and is; in effect it is a fallback, not a decision. There is no interaction that changes the valuation of a card depending on what you already have beyond the bottleneck arithmetic, no card that scales with layout, no card that punishes greed, no material that needs two processors in a non-linear order, no demand side (every dock pays list price, nothing is ever over-supplied). The DESIGN log is honest about this: the Sieve was cut because the 8×6 grid never forces a merge, and the two PLAN-v1 gates (pick-rate bands) failed and were widened rather than tuned, which is the right scientific call but also a signal that the content has one correct answer.

**Mastery ceiling for months of dailies.** Not there. Opus Magnum's 3 metrics × ~40 puzzles create a ceiling players chase for years because optimising cycles vs cost vs area pulls in different directions; shapez 2 has dozens of buildings and infinite shape complexity; Mini Motorways has ~13 maps whose traffic dynamics are chaotic enough that the same map plays differently every day; Balatro has 150 jokers × 15 decks × 8 stakes and multiplicative synergies. Junkyard Draft has 7 kinds, 5 materials, one objective and a throughput cap that is reached by round 3 on a good seed. The second axis (fewer machines) is a tie-breaker only. The verified-histogram framing — the best thing in the product — will show every competent player piled into a narrow band near the bot par, with the top of the board decided by who rerolled luckily. A month of dailies is survivable for a dedicated group; six months is not without more rules content.

## 3. Session and retention design

**Session.** A run is 5–8 minutes at 1× (80 ticks × 170 ms = 13.6 s per round plus building), under 3 minutes with 4× and Skip. Retry/random/daily are one click from results. This is the right size for a daily.

**What exists.** Daily with a 48 h window (generous and fair across time zones), weekly, archive as practice, forgiving streak with grace and no loss shaming, medals only after close and only with ≥ 5 runs (no fake podiums), bot par so day one has a target, groups, challenge links, forks, share card/text/clip. Everything is honest: no invented competitors, nothing unverified labelled verified, no dark patterns anywhere.

**What a day-30 player does.** Opens the title, sees the strip ("You: #k of n · $score · 1. $x Name"), plays today's seed once (unlimited attempts are allowed but the reveal gate and keep-best make the first attempt the one that matters socially), maybe reroll-fishes a second run, watches #1 if they are behind, forks it from round 3 to see what they missed, posts the glyph grid. The weekly gives one more seed per week. That is a Wordle-shaped habit — which is fine — but Wordle's retention comes from its five-minute cap and social ubiquity; this needs a hosted board and a crowd before any of it is real. Right now a day-30 player does not exist.

**Missing.** No meta progression of any kind (deliberately — DESIGN says nothing in progression changes scoring; that still leaves cosmetic and informational progression on the table). No profile / stats page (bests by seed live in localStorage and a two-line title panel; no history, no best-round, no percentile-over-time). No achievements beyond three unranked badges. No cosmetics, skins, palettes or themes. No modes: no endless/survival, no weekly modifier (explicitly deferred because a modifier is a rules bump), no puzzle campaign or authored levels (the tutorial is the only authored content), no difficulty settings. No music. No art beyond the procedural/SVG atlas. No mobile/touch (0.8.8 ⚑), no localisation (0.8.6), no gamepad (0.8.3), no screen reader (0.8.5). No friends beyond a group code; no notifications or "your friend beat you" loop (the Discord webhook is operator-side). No onboarding into the social layer (nothing tells a new player what a group is for or why to claim a name until they submit).

## 4. Onboarding and clarity

**First run.** A fresh device sees "Learn to play (3 min)" as the primary button, Enter on the title starts the tutorial, and the first non-tutorial draft shows "New here? 'Learn (3 min)'…". The tutorial's hint copy is good: it names the machine, the price, the orientation rule and the exact move ("drag the conveyor right after the hopper down to the bin … drop the crusher there with its arrow pointing right"), and it reacts to the real layout ("Raw scrap would reach the furnace first and melt into slag: move the furnace after the crusher"). Round 3 (splitter + side-load merge with spare conveyors) is the hardest step and the hint is dense; a player who does not read a 60-word paragraph will stall there. Nothing is modal, nothing is animated; the teaching channel is one 2-line strip at the bottom of the grid, below the parts bin, which is the least looked-at place on the screen (shots 02–05).

**Tips.** Seven tips with live demos that cannot lie (a strong idea borrowed from Factorio). They are discoverable only through a small "Tips" button and the ● badge after a first draft; the panel reads as documentation, not as a moment.

**Placement reasons.** Refusals (cell occupied, out of bounds) and warnings (nothing feeds it, points off the grid, tuner with nothing to tune) are specific and in plain language. They appear in the hint strip for ~2 s plus a red cell flash — easy to miss.

**What a new player will misunderstand** (from the decision log, the tips and what the UI shows):
- *Orientation is the whole puzzle* but the machine art signals it weakly: the amber arrow is small, the hopper's chute and the dock have no arrow, and the splitter's outputs go sideways from an arrow-less body. In shot 02 the five starter machines read as icons, not as a flow.
- *"From behind only"* vs conveyors' side-loading — the single most important rule — is conveyed by text only.
- *Furnace melts raw scrap to slag* — a trap by design (cheap lesson), but the furnace card says "Raw scrap melts to Slag ($1)" in the same tone as everything else.
- *The hopper cap.* Nothing on screen says 40 items per round or that a furnace at 3 ticks handles 26 of them; the badge "blocked 13" after the round is the first hint, and the fix (tuner, splitter, second line) is not suggested. The DESIGN throughput facts never reach the player.
- *Reroll costs score* and is disabled at $0 with a grey button and a sentence; players will not understand why it is grey in round 1.
- *Why rounds 4–6 did nothing.* The round history shows $444/$446/$446 and the diagnostics say "Hopper blocked 38 ticks"; nothing says "your line is saturated, you need a second hopper *and* a second crusher".
- *Local vs verified.* The copy is scrupulous ("local score, not yet verified", "not verified online") to the point of being apologetic; a new player does not know what a verifier is.

**Results with no verifier reachable** (shot 06): the big score, "NEW LOCAL PERSONAL BEST", round bars, what shipped, an empty "LOCAL VERIFIED BOARD · THIS SEED" panel with no body at all, a row of 13 buttons, and a small monospace status line "No local verifier running (optional: npm run verifier). Local bests are unverified." The title strip says "Verifier offline (optional: npm run verifier)". Developer language on the player's screen; the empty board panel is a visible hole; the histogram, bot par and medals simply do not exist in this state, so the headline feature of the results screen vanishes silently for anyone not running a Node process. In a hosted product "offline" should degrade to a cached board or an explicit "you're offline — your run is saved and will be submitted" affordance (nothing queues submissions today).

## 5. Audio-visual identity

**What it is.** A warm-industrial palette (charcoal #1a1612-ish floor, amber #f0a830 accents, rust/steel/green bodies), machines as 72 px rounded tiles with bolts, items as tiny 24 px shapes, DOM chrome in a system sans with amber small-caps headings and a monospace for meta text. Textures come from an authored SVG atlas with procedural fallbacks; all audio is synthesised at boot with two sampled impacts. It is coherent, legible, accessible and consistent, and it looks like a very good prototype or an internal tool, not a game people will screenshot. Specifically:

- **The grid dominates the screen but is 80 % empty** at every stage (shots 02–05b): 48 cells for at most 11 machines. On 1920×1080 (shot 16) the 1120×700 fixed layout scales up and the emptiness scales with it. There is no backdrop, no junkyard, no workshop, no fiction — just a dark grid with faint lines.
- **No logo**: the wordmark is letter-spaced bold amber text in two sizes. No icon language beyond the machine tiles; every control is a text button of the same grey; 13 near-identical buttons on the results row.
- **Hierarchy** is carried entirely by type size and amber vs grey; the score is the only large element. The draft cards (shot 02) are the best-composed element in the game. The hint strip and the parts bin are undifferentiated boxes.
- **Motion** is restrained by design (nothing shakes, idle machines are still). That is a sound accessibility decision, but the result at 1× (shot 04) reads as static: three items, a progress bar and a small "+$12". The "run is the show" goal from PLAN-v1 is not visible in a still.
- **Audio**: functional synth blips and chords; the fanfare and the hum are the only moments with character. No music means no mood between rounds and no signature.
- **Share card** (`card.ts`): a dark panel with a big number and six bars, correct and honest, visually generic; the block-glyph string `░▒▓█` rendered as a white block in the share-text dialog on this machine (shot 07, a font fallback issue STATUS already met on the card).

**Against peers.** Mini Motorways: a single colour palette per city, every element from one grammar, motion designed for screenshots. shapez: flat icons but a strong shape language and satisfying belt density. Balatro: a CRT shader, authored card art, a soundtrack people stream. Opus Magnum: bespoke art, a signature GIF export that *is* the marketing. Junkyard Draft's GIF/WebM export is the right instinct, but the frame it exports is the empty grid above.

**A production pass needs**: an art direction (what is a junkyard? where are the piles, the crane, the weather?), authored machine art with unmistakable input/output silhouettes and 2–4 idle/working frames each, a background and grid treatment that fills 1280–1920 widths without scaling a 1120 canvas, item art with mass, a logo and icon set, a UI design system (type scale, button hierarchy — primary/secondary/tertiary/icon, panels, toasts replacing the hint strip for refusals), a results screen composed around the histogram with the actions grouped, 2–3 music loops (build / run / results) that the hum can sit under, a trailer cut from clips and a store-page set of shots at 1920×1080.

## 6. Modes and audience fit

**Who it is for.** People who liked Opus Magnum's histograms and Mini Motorways' daily, who want a 5-minute deterministic optimisation puzzle with a fair board, and who care that the score cannot be faked. That audience is real but small and skews towards players who will see through 7 machines in a week. The design also appeals to a second group — Wordle-style daily-habit players — who need stronger onboarding, prettier shares and a visible crowd.

**Where the fun is.** Two moments: pressing RUN on a layout you changed and watching the line come alive (build-and-watch payoff — currently underpowered visually), and seeing your bar on the histogram next to the bot par and the top players (currently invisible without a hosted verifier). Everything between — picking the obviously correct card, dragging it into the obviously correct cell — is procedure.

**What would make it "extremely fun, ethically addictive and social" within the project's rules** (same seed for everyone, deterministic sim, replay verification as the only truth, no dark patterns):
- More *interacting* content so the draft is a real decision (see Bold ideas), each new kind gated by the same balance tooling (`tools/balance.ts --gate`) so the "no seed worse" discipline stays.
- A weekly **modifier** (a rules-version-bumped ruleset variant, e.g. "furnaces hold 2, docks pay half for scrap") — the project deferred it as a rules bump; a *versioned* modifier table is exactly what `RULES_VERSION` is for.
- A visible crowd: live counts ("412 verified runs today, median $1,610"), the histogram on the *title* strip and on the share card, a group's weekly digest. All read-only, all from the verified board.
- A player-facing **"why"** after each round (the bottleneck named: "hopper blocked 38 ticks — your furnace is full; a tuner or a second furnace would take it"), built from `CellStats` the sim already has. This turns the silent plateau into a goal.
- Forks as the social loop they could be: "watch #1 → fork from round 3 → beat their round 4" is already there; it needs a scoreboard of its own ("best continuation of today's #1") to become a mode.
- Authored puzzles ("ship 30 ingots with 7 machines", "no tuners", "two docks") on fixed seeds with histograms per puzzle: Opus Magnum's campaign shape with Junkyard's verification. Scenario namespaces already exist (`tutorial-*`) and are versioned.

## 8. Five quick wins (perceived quality per unit of work)

1. **Rewrite the offline/verified copy and fill the empty board panel**: "Offline — your run is saved on this device; connect to compare with today's players" instead of "npm run verifier"; show the local seed history in the board panel when the verifier is away; group the 13 results buttons into Play / Share / Replay rows with one primary. Also shown as the hint during the next draft. (GamePanel.badgeNotes; sim-free.)
3. **Make orientation visible**: a larger output arrow on every machine, an input notch on the "from behind only" machines, and a translucent flow arrow drawn across the whole line in the build phase (the sim already knows `inputTravelDirs`/`outputDirs`). (textures/atlas + GameScene ghost layer.)
4. **Fill the frame**: a backdrop (yard, fence, crane silhouette, pallets) around the grid, a subtle floor texture, and a layout that uses 1280–1920 widths instead of scaling a 1120 canvas; place the parts bin *beside* the grid so the hint strip moves up next to the action. ## 9. Five bold ideas worth asking the owner about

1. **Weekly modifiers as versioned rulesets** (precedent: *Slay the Spire* daily climb modifiers, *Mini Motorways* weekly challenges). A small table of named rule variants (`RULES_VERSION` branches with their own golden corpus) applied to the weekly seed: "hot furnaces" (hold 2), "scrap glut" (hopper period 1, scrap $0), "two docks", "no tuners". Each is a rules bump the policy page already knows how to describe, and `tools/balance.ts` can gate each. It multiplies the content without new art.
2. **A demand board — the dock pays what the market wants** (precedent: *Factorio*'s science packs / *shapez*'s delivery goals, *Opus Magnum*'s multi-product puzzles). Each seed publishes a small order list ("12 plates at $11, then ingots at $9") that every player sees identically. Suddenly the press has a reason, over-production has a cost, and the draft has tension that the hopper cap cannot flatten. Deterministic, seed-fair, replay-verified by construction.
3. **Authored puzzle campaign with per-puzzle histograms** (precedent: *Opus Magnum*'s 36 puzzles with cost/cycles/area histograms; *Zachtronics* generally). Thirty hand-made starting layouts and inventories on reserved `puzzle-*` seeds with two or three objectives each (money, fewest machines, fewest ticks to first ingot), verified by the same replay pipeline. This gives the game a shape players can finish and a reason to return between dailies, and it is the natural home for a Steam page.
4. **"Beat the ghost" asynchronous duels with stakes-free leagues** (precedent: *Wordle*/*Connections* group threads, *Golf Clash*'s league tiers, *Trackmania*'s medal ghosts). Groups already scope boards; add a weekly league table per group (points by daily rank), a ghost overlay of the group leader's layout *after the day closes*, and a digest message.
