# PLAN-v5 — v0.8 "Everywhere it should run", re-cut after 0.7.0

Written 2026-10-30 at `main` after the 0.7.0 release (verifier protocol 2, rules version 3). It replaces the v0.8 section of `docs/PLAN-v1.md` and folds in the v0.8 additions of `docs/DOSSIER-v1.md` §7 (relay, Linux build, custom Phaser build, touch). Same format as PLAN-v2 to PLAN-v4: binding policies first, then numbered, sized increments with *What / Why / Accept*. Sizes: S ≤ half a day, M a day or two, L longer. ⚑ needs a human. **No rules change in v0.8**: `RULES_VERSION` stays 3, the golden corpus is not regenerated, every increment is replay-compatible, and the verifier's protocol stays at 2 (everything added is additive and nothing a client must detect).

## 0. Where we start

Shipped in 0.7.0: challenge links, groups by code, forks, the share card, the weekly seed, the Discord webhook, the first cut of name moderation, and the hot/cold storage split; 149 tests, a game e2e and a render e2e in headless Chromium, the Docker smoke and the mint check in CI, the rollback rehearsal and the autoplay sweep as release evidence.

Still open, and still the gate for ranked play: **the verifier is not hosted (0.7.8 ⚑)**. PLAN-v4 said v0.8 would wait for the beta's first numbers; it is written now because every item below can be built and proven against the local verifier and headless browsers, and none needs a crowd, a server, or a player to exist first. The two things that do need the beta stay gated: **0.7.0b SQLite** (a measured month over 5 MB or 50 ms) and the **relay** of DOSSIER-v1 §5.2 (presence, watch-together, races), which needs two people online at once and a process beside a hosted verifier, and so moves to PLAN-v6 with the trigger named in §3.

What is already true, so the re-cut is smaller than PLAN-v1's: the canvas already scales (Phaser `FIT` with the DOM overlay following it through `--k`, DOSSIER 0.4.0), DPR rendering exists, three text sizes and a WCAG AA + CVD audit run in the suite, keyboard placement exists with a grid cursor and fourteen bindings, the sim uses mulberry32 and integer arithmetic with no `Math.sin`, the verifier already has body caps, a per-player bucket, atomic writes, duplicate rejection and the action cap (`MAX_REPLAY_ACTIONS` 4000), the golden corpus re-simulates every file, and the Electron config already declares a Linux target. Measured today: `dist/main.js` is 1384 KiB, 390 KiB gzipped.

## 1. Policies that bind every increment

**No rules change.** Determinism is proven, not repaired: if 0.8.0 finds an engine that disagrees with Node on a golden replay, the fix is in the sim and bumps `RULES_VERSION` on a `rules-v4` branch, never a silent patch. The lint rule of 0.8.0 is part of the suite from then on.

**Accessibility and input never change offers or scoring, so all of it is allowed in the ranked daily.** Sim speed, pause, single-step, undo before the run, text size, contrast, motion, the handheld preset, gamepad, remapping and the screen-reader mirror change nothing about what a seed offers or what a run scores (PLAN-v1 cross-cutting). Anything that would add hints inside a run or alter offers belongs in practice and is not in this plan.

**One action table.** Every input device (mouse, keyboard, gamepad, the screen-reader mirror) maps to the same named actions (`place`, `rotate`, `pickUp`, `returnToBin`, `cycleBin`, `run`, `speed`, `undo`, `redo`, `pause`, `step`, `confirm`, `cancel`); no device gets an action another lacks; the dev API drives the same table. Prompts and tutorial text read the current binding from the table, never a literal key name.

**Hosting is still the gate** (PLAN-v3 §1, PLAN-v4 §1). Nothing in v0.8 may need a server that does not exist yet; nothing may remove the local path.

**Strings.** Every user-visible string moves to one keyed table with placeholders; numbers are never concatenated into prose; the pseudo-locale (30–50 % longer, accented glyphs, brackets) runs in the e2e so a wrapping regression is caught in CI, where the Linux font stack already wraps differently (the 9c8205b lesson). No translations in v0.8; the table is the prerequisite, not the product.

**Budgets.** `tools/perf.ts` stays the gate for every increment that touches rendering or input (0.8.1, 0.8.3, 0.8.4, 0.8.9); `dist/main.js` gzipped must not grow past 420 KiB before 0.8.9 and `tests/quality.test.ts` measures it; the verifier's request path never waits on anything but the re-simulation itself, and 0.8.7 bounds that too.

**Protocol compatibility.** Protocol stays 2. Reason codes (0.8.7) are added beside the existing `error` strings, never instead of them; a 0.7.0 client keeps working unchanged.

**Evidence.** As before: unit tests, an e2e against a spawned verifier where the client changed, the Docker smoke extended when an endpoint changes, STATUS numbers, instrumented copies of a flaky test rather than guesses, and no fabricated results. Where Playwright cannot emulate a device (gamepads), the plan says so and names the injected substitute.

## 2. The increments, in dependency order

**0.8.0 Determinism proven across engines, and a lint that keeps it** — S/M. *What:* `tools/make-golden.ts` also records, per golden replay, the SHA-256 of the final run state and of the per-tick event stream of every round (new fields in the corpus files, no replay regenerated); `tests/engines-e2e.test.mjs` loads the sim bundle in Chromium, Firefox and WebKit through Playwright and compares every corpus hash with Node's; CI installs the three engines for that job only. `tests/determinism-lint.test.ts` greps `game/src/sim/` for `Math.random|sin|cos|tan|exp|pow|log|atan`, `Date`, `Intl`, `toLocale`, `performance.now` and comparator-less `sort(`, with an explicit allowlist for the two calendar modules (`daily.ts`, `weekly.ts`) that are date helpers and not simulation, and fails on anything else. *Why:* PLAN-v1 0.8.1: one documented V8-vs-V8 divergence came from `sin/cos`; the sim avoids them already, so this is proof plus a tripwire for the next contributor. *Accept:* the three engines agree with Node on every corpus file; the lint test fails on an injected `Math.sin` in `sim.ts` and on a `sort()` without a comparator; `npm test` adds the lint and CI adds the engine job (the local suite keeps Chromium only unless the other engines are installed, and says so).

**0.8.1 Handheld preset and the scaling check** — S. *What:* a "Handheld" preset in settings (title button beside text size) that sets the text scale so the smallest rendered glyph is ≥ 12 px at 1280×800, raises hit targets to ≥ 40 logical pixels for the bin slots, offers and the HUD buttons, and persists; an e2e at 1280×800 and 1920×1080 asserts no clipping of any `[data-testid]` against the overlay (the existing title layout check generalised) and measures the smallest font size in the preset; `tests/a11y.test.ts` gains the preset's sizes. *Why:* PLAN-v1 0.8.2 (Deck Verified wants 12 px at 1280×800; XAG 101 wants 18 px body text at 1080p). The canvas already scales; what is missing is the preset and the proof. *Accept:* both viewports pass the clipping check with and without the preset; the perf gate is unchanged at 4×.

**0.8.2 The action table and full key remapping** — S/M. *What:* `game/src/render/actions.ts` names every input action and holds the default bindings (today's fourteen `keydown-*` handlers in `GameScene`, plus `step`); a "Controls" settings panel rebinds any action (one key per action, conflicts refused with the holder named, reset to defaults), persisted under `jd.controls.v1`; the HUD hints, the tutorial text and the how-to list read the current binding; the dev API's key-driven paths go through the table. *Why:* PLAN-v1 0.8.5 (GAG Basic: remappable controls; Opus Magnum's undocumented-controls complaint cluster); the table is also what 0.8.3 and 0.8.5 bind to. *Accept:* e2e rebinds rotate to another key, the hint text names the new key, the old key does nothing and the new one rotates; a conflicting rebind is refused with a message; reset restores the fourteen defaults; the keyboard e2e still passes.

**0.8.3 Gamepad over the keyboard cursor** — M. *What:* the Gamepad API polled once per frame in the scene update: d-pad and left stick move the grid cursor, face buttons map to `place`/`pickUp`, `rotate`, `returnToBin` and `run`, shoulders cycle bin parts and speed, start pauses, with activation on release and a cancel path (XAG 107); on-screen prompts switch glyph set (keyboard or Xbox-style letters, never vendor logos) by last input; the title and results are navigable by the same buttons; no text entry is required to play (name entry stays a keyboard or on-screen affair). Playwright cannot emulate a gamepad, so the mapper takes a `GamepadState` snapshot and the dev API gains `window.__jd.gamepad(state)` to inject one; the mapping itself is a pure module with unit tests. *Why:* PLAN-v1 0.8.3 (Deck Verified: controller works without settings changes, glyphs match the active input). *Accept:* unit tests for the mapper (edge detection, release activation, repeat on held d-pad, stick dead zone); e2e completes a round through injected gamepad states and the glyph set switches in a screenshot; the keyboard and mouse e2e still pass; the perf gate is unchanged.

**0.8.4 Single-step while paused** — S. *What:* while a run is paused, `step` advances exactly one tick (the panel button and the bound key); the HUD shows the tick; speed and pause behave as before; replays and forks can be stepped too. *Why:* PLAN-v1 cross-cutting: the largest Opus Magnum debugging complaint is the lack of stepping, the sim is a pure function of (layout, tick) so this is cheap, and it changes nothing about outcomes. *Accept:* e2e pauses, steps three times, reads the tick counter, resumes and finishes with the same score as an unstepped run of the same actions; a sim test that stepping tick by tick reproduces the batch result for every golden replay.

**0.8.5 Screen-reader mirror of the grid** — M. *What:* a visually hidden DOM region beside the canvas (the overlay already hosts the chrome): the 48 cells as an APG grid with roving tabindex, each labelled ("row 3, column 2: furnace, facing east, fed from the west"), the offers as a listbox, the bin as a list, one polite live region for state changes ("placed crusher at C3 facing east") and one assertive region for rejections (reusing the 0.3.2 rejection strings), and the run reported as one summary per round; every action goes through the 0.8.2 table so the mirror can place, rotate, return and run. Not in scope: a tick-by-tick narration of the run. *Why:* PLAN-v1 0.8.4 and DOSSIER §7 (grid only); a canvas is opaque to assistive technology, the game is turn-based and keyboard placement exists, so the delta is labelling and announcements. *Accept:* Playwright's ARIA snapshot lists 48 labelled cells, the offers and the bin; an e2e completes a round using only the mirror (focus, arrow keys, Enter) and reads the two live regions; the existing a11y audit still passes; recruiting a screen-reader tester is a v0.9 human item.

**0.8.6 Externalised strings and the pseudo-locale** — M/L. *What:* `game/src/ui/strings.ts`: one keyed table with ICU-style placeholders for every user-visible string in `game/src/ui/`, `game/src/render/scenes/` and the share, card and policy renderers (the policy page's generated sentences stay generated but through the same placeholder helper); a `?locale=pseudo` mode lengthens every string by 30–50 % with accented glyphs and brackets; containers wrap or ellipsise; a glyph-coverage check for the font stack against the pseudo-locale alphabet. `tests/strings.test.ts` fails on a string literal rendered outside the table (an allowlist for test ids, CSS, seeds and formats). No translations. *Why:* PLAN-v1 0.8.6; cheap now, expensive later, and the Linux-font CI failure of 9c8205b was exactly the class of bug a pseudo-locale catches before a translator does. *Accept:* the literal test is green with an allowlist that is listed, not grepped; the pseudo-locale e2e passes the title, build and results layout checks at 100 % and 130 % text; the share text and card footer wording tests are unchanged.

**0.8.7 Verifier hardening: reason codes, bounded verification, void-day** — M. *What:* every refusal from `/verify` carries `reason: 'did_not_reproduce' | 'unfinished' | 'rules_version' | 'duplicate' | 'invalid_seed' | 'outside_window' | 'too_large' | 'rate_limited' | 'forked'` beside the existing `error` text, and the client's `daily_submit_result` event uses it; re-simulation runs in a worker with a wall-clock timeout (the par worker's pattern) when the replay is longer than a measured threshold, so a pathological 4000-action replay cannot hold the request path, and the timeout answers 422 `did_not_reproduce` with the time named; `tools/void-day.ts <url> <date> --token` marks an issued day void (its board hidden from `/daily` and `/archive` with the reason, its entries kept, a replacement seed minted for the rest of the window) and appends to `moderation.jsonl`; `server/README.md` gets the runbook line "a day whose outcomes a bug has compromised is voided and re-issued, never re-scored". *Why:* PLAN-v1 0.8.7 minus what 0.5–0.7 already did (caps, bucket, atomic writes, cold storage) and minus SQLite (0.7.0b, by measurement); the void path is the one integrity tool the runbook promises and does not have. *Accept:* a verifier test per reason code; a planted slow re-simulation times out without blocking a concurrent `/health`; the void tool hides the day, mints the replacement, keeps the entries and writes the audit row; the Docker smoke reads a reason code from a refused submission; a 0.7.0 client's assertions on `error` still hold.

**0.8.8 Linux build in CI and touch input** — S/M, ⚑ for the device run. *What:* the release workflow adds an Ubuntu job producing the AppImage from the existing `linux` target and runs the packaged smoke against it; the game's drag, rotate (two-finger tap or a long press) and the panel buttons work under Playwright's touch emulation (`hasTouch`, a 1280×800 tablet viewport), with the handheld preset applied automatically when the primary pointer is coarse. *Why:* DOSSIER §7 0.8.10 and 0.8.12; the Deck wants a native Linux build rather than Electron under Proton (Boson's authors), and a web build on a tablet is the cheapest second platform. *Accept:* CI publishes the AppImage artifact and its smoke passes; a touch e2e drags a machine to a cell, rotates it and runs a round; the ⚑ part is a run on a Deck or a Linux laptop recorded in STATUS.

**0.8.9 Custom Phaser build** — M, measured. *What:* an esbuild entry that pulls only the Phaser systems the game uses (WebGL and Canvas renderers, Scale, Input with gamepad, Tweens, Text, Graphics, Sprite, Container; no Physics, Sound, Tilemaps, Particles, Lights, DOM elements, Spine) through Phaser's custom-build path, behind the one build script; gated by the measured gzip size, target ≤ 250 KiB gzipped (from 390). *Why:* DOSSIER §7 0.8.11; load time on the web build is the first-session funnel's first step. *Accept:* `npm test` green on the custom build; `tools/perf.ts` shows identical draw counts and frame times; the quality test pins the new size; if the saving is under 25 % the increment is closed as "measured, not worth the second entry point" and the budget stays.

**0.8.10 ⚑ Steam plumbing behind a build flag** — L ⚑ (unchanged from PLAN-v1 0.8.8). *What:* a Steam-only Electron build (separate from the web build so the web keeps its strict CSP) with `steamworks.js` for achievements, rich presence, Auto-Cloud and the Deck check; the verifier validates `GetAuthTicketForWebApi` tickets, binds the SteamID to the `player_id`, and writes verified scores to a trusted-write Steam leaderboard. The Steamworks app fee and the publisher key are the owner's. What the routine may pre-build without them: the build flag and the bundle-size check that the web build carries no Steam code, and the ticket → SteamID → board-write path against a mocked Steam Web API with its tests. *Accept:* the mocked path test; the web bundle contains no Steam code (size and symbol check); the rest waits for the key.

## 3. What the nightly routine may take, and what waits

0.8.0–0.8.9 are `main` work with no rules change; each is one commit with its tests, regenerates the policy page only if a rule of conduct changes (none planned), and extends the Docker smoke when a response changes shape (0.8.7). 0.8.10's mocked slice may be taken; its Steam half is the owner's. **0.7.0b** runs only when a measured beta month says so. **0.7.8 ⚑ hosting** is the owner's and is still the gate for ranked play.

**Waits for PLAN-v6 (v0.9 beta), with triggers:** the relay of DOSSIER-v1 §5.2 (presence, watch-together, races with ready-up, spectator URL) once the hosted verifier has logged two or more verified submitters inside any ten-minute window on ten different days (presence derived from verifier timestamps, no new client data); playtest round two with a screen-reader user and a controller-only user (PLAN-v1 0.9.1), which 0.8.3 and 0.8.5 make possible; Human and Assisted boards (0.9.2); anomaly signals (0.9.4); the privacy page (0.9.5 ⚑); the Steam page and Next Fest (0.9.6 ⚑); the rules freeze (0.9.7).

## 4. Metrics and risks

Watch (from the suite, CI and the funnel, never from names): zero engine disagreements on the corpus across CI runs (the 1.0 exit criterion of 30 days with no `did_not_reproduce` on valid replays starts counting here); share of sessions with a gamepad as last input once the Linux build exists; share of players who change the text size or pick the handheld preset; rejected-placement counts before the first valid one in the mirror e2e (a proxy for label quality until a tester is recruited); `dist/main.js` gzipped per release; verifier p95 of `/verify` on the dev PC before and after 0.8.7.

Risks: the engines job adds Firefox and WebKit to CI and both have had Playwright install breakage on Ubuntu (mitigation: the job is separate, non-blocking for one release, and the local suite keeps working without them); the gamepad path cannot be proven on a real device in CI (mitigation: the mapper is pure and unit-tested, the e2e injects states through the same path the poller uses, and the Deck run is a named ⚑ item); externalising 160+ strings is a wide mechanical change (mitigation: the literal test lands first with the allowlist equal to today's strings and shrinks per file, so every step is green); the screen-reader mirror is designed from standards, not from a tester (mitigation: grid-only scope, and the v0.9 playtest names a screen-reader user); a custom Phaser build can diverge from upstream fixes (mitigation: measured gate, one build script, closed if the saving is small); the void-day tool is powerful (mitigation: moderator token, audit row, the replacement seed is minted from the same chain and announced through the webhook as a re-issue, never silently).
